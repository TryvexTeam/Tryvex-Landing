¿Cómo manejamos los estilos?

El landing tiene un sistema CSS propio muy trabajado. Tailwind v4 entra al equipo — hay que decidir cómo conviven.

Lo que ya tenemos y no queremos perder

--ink → #0e0e0e /* negro editorial */
--paper → #f4f1ea /* crema cálido */
--vex → oklch(65% .18 28) /* rojo-naranja marca */
--signal → oklch(65% .12 250) /* azul acero */
--glass-bg → rgba(255,255,255,0.42) + blur(28px) saturate(180%)
--grain → SVG noise texture, opacity .03
fonts → Geist + JetBrains Mono + Instrument Serif

Tres estrategias de estilos para Next.js + Tailwind v4

Opción A — Solo Tailwind
Migrar todo a clases utility
<div className=
 "bg-[#0e0e0e]
  backdrop-blur-2xl
  text-[#f4f1ea]
  rounded-xl">
✓ Sin CSS externo
✗ Valores oklch hardcodeados en JSX
✗ Tokens glass imposibles de mantener
✗ Se pierde el sistema actual
Recomendada
Opción B — Tokens CSS + Tailwind
CSS Variables como fuente de verdad
/* tokens.css */
:root {
 --color-ink: #0e0e0e;
 --color-vex: oklch(65% .18 28);
}

/* tailwind.config.ts */
colors: {
 ink: 'var(--color-ink)',
 vex: 'var(--color-vex)'
}

/* JSX */
className="bg-ink text-vex"
✓ Tokens preservados y centralizados
✓ Tailwind usa los valores reales del sistema
✓ Dark mode: un solo swap de CSS Variable
✓ Glass y grain como plugins Tailwind
Opción C — CSS Modules
Un archivo CSS por componente
Hero.module.css
Services.module.css
Pricing.module.css
GlassCard.module.css
/* +15 archivos CSS */
✓ Scoping automático por componente
✗ Más código, sin utility classes
✗ No aprovecha Tailwind v4
✗ Duplicación de tokens entre módulos

Con la Opción B, el sistema visual queda así en Next.js

styles/tokens.css → layout.tsx

Importado una sola vez en el layout raíz. Contiene todos los CSS Variables: colores, glass, grain, spacing y radii del sistema Tryvex.

tailwind.config.ts extendido

Los colores ink, paper, vex, signal disponibles como clases utility. bg-ink, text-vex, border-signal en todo el proyecto.

Plugin glass-light / glass-dark

El backdrop-filter + rgba quedan definidos como plugin de Tailwind. Una sola clase glass-light activa todo el efecto glassmorphism.

Tipografía vía next/font

Geist, JetBrains Mono e Instrument Serif con next/font/google. Zero layout shift, subconjunto automático, sin CDN externo.

✅ Recomendación: Opción B. CSS Variables como fuente de verdad + Tailwind como capa utility. El sistema glassmorphism de Tryvex se preserva sin perder nada. Siguiente pregunta → ¿estrategia de animaciones con Framer Motion?
