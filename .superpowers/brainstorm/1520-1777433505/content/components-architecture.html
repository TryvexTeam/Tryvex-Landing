¿Cómo organizamos los componentes?

El landing tiene 11 secciones. La estructura que elijamos hoy define cuánto duele escalar mañana.

Las 11 secciones del landing actual

<Navbar /> <Hero /> <LogoStrip /> <Services /> <Process /> <Metrics /> <Testimonial /> <Pricing /> <FAQ /> <CTAFinal /> <Footer />

Tres enfoques de organización

Opción A — Plana
Una carpeta, todo junto
src/
├── app/
│   └── page.tsx
└── components/
    ├── Navbar.tsx
    ├── Hero.tsx
    ├── Services.tsx
    ├── Process.tsx
    ├── Metrics.tsx
    ├── Pricing.tsx
    ├── FAQ.tsx
    └── Footer.tsx
✓ Setup en minutos
✓ Sin fricción inicial
✗ components/ se llena de 20+ archivos
✗ CSS compartido sin estructura
Recomendada
Opción B — Sections + UI
Secciones por carpeta, UI compartida
src/
├── app/
│   └── page.tsx
├── components/
│   ├── sections/
│   │   ├── Hero.tsx
│   │   ├── Services.tsx
│   │   ├── Pricing.tsx
│   │   └── ...
│   └── ui/
│       ├── GlassCard.tsx
│       ├── AnimatedText.tsx
│       ├── Counter.tsx
│       └── Button.tsx
├── hooks/
│   ├── useScrollProgress.ts
│   └── useReducedMotion.ts
└── styles/
    └── tokens.css
✓ Secciones aisladas, fácil de editar
✓ UI reutilizable sin duplicar
✓ hooks/ separa lógica de animación
✓ Escala naturalmente al crecer
Opción C — Atomic Design
Atoms → Molecules → Organisms
src/
├── app/
│   └── page.tsx
└── components/
    ├── atoms/
    │   ├── Button.tsx
    │   └── Badge.tsx
    ├── molecules/
    │   ├── PricingCard.tsx
    │   └── ServiceCard.tsx
    └── organisms/
        ├── Navbar.tsx
        └── PricingSection.tsx
✓ Máxima separación
✗ Overhead para un landing
✗ Fricción sin Design System real
✗ Overkill en Sprint 0

Componentes UI compartidos que reutilizaremos

GlassCard

El contenedor glass que usan Services, Metrics y Pricing. Un componente con variantes light/dark en vez de CSS repetido.

AnimatedText

Word-split + reveal con Framer Motion. Reemplaza el IntersectionObserver manual en todos los headings.

Counter

Contador animado para la sección Metrics. Lógica de animación en hook propio: useCounter.

SectionWrapper

Envuelve cada sección con padding uniforme + motion.section de Framer para fade-up al entrar en viewport. Reemplaza el IntersectionObserver global.

✅ Recomendación: Opción B. Sections + UI compartida — equilibrio entre orden y velocidad para Sprint 0. Siguiente pregunta → ¿cómo manejamos los estilos y tokens CSS?
